# 国标目录规划模板（按场景）

本文给出可直接照做的目录规划模板，覆盖智慧小区、智慧工厂、公共安全（行政区划）以及混合组织。
每条规则都对应平台现有实现，照此规划可保证：推送到上级的目录能挂上树、编码不冲突、后续增删不出错。

---

## 0. 先分清三个概念

| 概念 | 说明 | 示例 |
|---|---|---|
| **通道/点位** | 实际摄像机、门禁等，平台内一份数据，带内部编码 | `53010000001310000001` |
| **国标目录** | 严格按国标码建立、用于对外级联的树。节点类型：215 业务分组、216 虚拟组织（行政区划节点同样用 216 类型） | `53000000002160000000`（云南省） |
| **共享** | 只针对国标目录里的 215/216 节点做勾选，节点下通道动态跟随 | 共享"五华分局"节点 |

**一个重要限制**：一个通道在国标目录里只能有 **一个父节点**。所以"车辆/人员"这类业务分类 **不要** 再建第二棵树，用标签或页面筛选实现；国标目录只承载 **组织维度**（区域、部门、楼栋）。

---

## 1. 编码规则速查

20 位国标码 = **中心编码(8) + 行业编码(2) + 类型编码(3) + 网络标识(1) + 序号(6)**

| 用途 | 类型码 | 示例 |
|---|---|---|
| 摄像机 | 131 | `53010000001310000001` |
| IPC | 132 | `53010000001320000001` |
| 业务分组（容器） | 215 | `53000000002150000001` |
| 虚拟组织（挂通道） | 216 | `53000000002160000001` |
| 行政区划节点（默认推导） | 216 | `530100` → `53010000002160000000` |

**行政区划节点默认规则**：区划码右补 0 到 8 位 + 行业 `00` + 类型 `216` + 网络 `0` + 序号 `000000`。
例：云南省 `53` → `53000000002160000000`；昆明市 `5301` → `53010000002160000000`；五华区 `530102` → `53010200002160000000`。

**上级指定编码**：省厅等上级若规定了区划节点编码，在「通道管理 → 行政区划 → 编码映射」中配置 `区划编号 → 20 位码`，推送时优先使用映射；未配置的按默认规则推导。

**无码设备**（ONVIF/插件接入的通道）：挂到 216 虚拟组织时自动分配 `平台前10位 + 131 + 0 + 6位序号`，分配后固化写回，不再变化。

## 2. 场景一：智慧小区（业务分组型，最常见）

### 规划
```
XX小区 (215 业务分组，仅容器，不放点位)
├── 1栋 (216 虚拟组织)      → 单元门口机、电梯摄像机
├── 2栋 (216)
├── 地库 (216)              → 车道摄像机、车位摄像机
├── 出入口 (216)            → 门岗摄像机、车辆抓拍
└── 公共区域 (216)          → 周界、广场
```

### 编码示例（平台编号 `34020000002000000001`）

| 节点 | 类型 | 20 位编码 |
|---|---|---|
| XX小区 | 215 | `34020000002150000001` |
| 1栋 | 216 | `34020000002160000001` |
| 1栋-单元门口机 | 131 | `34020000001310000001` |
| 地库 | 216 | `34020000002160000003` |
| 地库-车道相机 | 131 | `34020000001310000005` |

### 操作步骤
1. 通道管理 → 业务分组：新建 215「XX小区」；
2. 在其下新建 216「1栋」「地库」等；
3. 设备接入后，在「业务分组」页把通道挂到对应 216；
4. 平台管理 → 上级平台 → 编辑 → 通道共享 → **按业务目录共享**，勾选「XX小区」保存；
5. 推送后，上级看到的就是 `XX小区 → 1栋/地库 → 点位`。

## 3. 场景二：智慧工厂

### 规划
```
XX工厂 (215)
├── 生产一车间 (216) → 产线摄像机、质检工位
├── 仓储区 (216)     → 仓库出入口、货架通道
├── 厂区出入口 (216) → 门岗、车辆抓拍
└── 办公楼 (216)     → 大厅、电梯、机房
```

规则同上。车间扩建时只加 216 节点和通道，已共享的 215 节点会自动把新内容带给上级。

## 4. 场景三：公共安全（行政区划型）

以云南省公安厅为例，下级（区县平台）向上级（省厅平台）提供目录。

### 规划
```
云南省 (530000，行政区划节点)
└── 昆明市 (530100)
    ├── 五华区 (530102) → 点位A、点位B
    └── 盘龙区 (530103) → 点位C
```

### 操作步骤
1. 通道管理 → 行政区划 → **按区划建树**：依次选 云南省 → 昆明市 → 五华区，确认后自动创建 `53 / 5301 / 530102` 三个节点（已存在会跳过）；
2. 若省厅规定了区划节点编码，在 **编码映射** 中录入，例如 `5301 → 53010000002000000077`；
3. 把点位挂到区县：行政区划页选中「五华区」→ 添加通道；
4. 平台管理 → 上级平台 → 通道共享（按通道或按业务目录均可）；
5. 推送后，省厅看到：
```
云南省            53000000002160000000（默认推导）
└── 昆明市        53010000002000000077（省厅指定编码）
    └── 五华区    53010200002160000000（默认推导）
        └── 点位A 53010000001310000001
```

### 注意
- 区划节点编号与点位编号的 **中心编码段** 建议同源（同一个 8 位中心码），便于上级按区划归集；
- 上级未指定编码时不要手工乱填，用默认推导最稳；
- 上级平台若要求 `ParentID` 指向上级系统编码，由上级侧配置根节点，本级不需要改。

## 5. 场景四：混合组织（区划 + 分组）

两种树可以并存，推送时自动合并：

```
云南省 (530000)
└── 昆明市 (530100)
    └── 五华区 (530102)
        └── 某小区 (215)          ← 区划下挂业务分组
            └── 1栋 (216)
                └── 点位
```

规则：
- 通道父节点优先取它挂的 216 虚拟组织；没有挂分组时按 `区划编码` 挂到行政区划节点；
- 两棵树的祖先链会自动补齐推给上级；
- 只共享时选一个节点即可，其子树（含另一种树的节点）一并带出。

---

## 6. 共享规则（对上级）

| 操作 | 结果 |
|---|---|
| 勾选 215/216 节点 | 该节点及其子树下所有通道共享给上级 |
| 共享后新增设备/通道挂到该子树 | 下次推送自动带给上级，无需重新共享 |
| 取消勾选 | 下次推送发删除通知（DEL），上级移除整棵子树 |
| 通道未挂任何目录节点 | 不共享；若被显式勾选共享，则挂到上级根节点 |
| 父节点缺失/编码不规范 | 上级标记为"未挂载"，只记日志，不影响其它节点 |

## 7. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 上级目录里节点是平的，没有层级 | 通道没挂 216/区划，或父节点没共建 | 按"按区划建树"补齐父级；通道挂到正确节点 |
| 上级提示"父节点不存在，暂不挂载" | 节点 `ParentID` 指向本级不存在的节点 | 补齐父节点后重新推送，会自动挂回 |
| 通道挂 215 被拒绝 | 215 只是容器，不能直接挂通道 | 在 215 下建 216 再挂 |
| 区划编号提示非法 | 行政区划编码不是 2/4/6/8 位或不在民政部编码表内 | 用「按区划建树」选择，不要手填 |
| 编码映射保存失败 | 对外码不是 20 位数字，或区划不存在 | 先建区划节点，再录 20 位码 |
| 推送报"未配置共享通道" | 该平台还没有任何共享 | 先共享节点或通道 |
| 大规模目录推送慢/失败 | 单包超 MTU | 平台已自动分批；如仍失败检查网络 MTU |

---

## 8. 一句话总结

- **园区/企业**：215 容器 → 216 部门/楼栋 → 点位；共享选 215。
- **公共安全**：行政区划一键建树 → 点位挂区县；上级指定编码就配映射。
- **业务分类**（车辆/人员）不要占国标目录，用标签。
- **一个点位一个父节点**，改结构就改挂载，不要改国标码。
