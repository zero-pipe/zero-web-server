# 接口与鉴权规范（平台 ↔ ZMS / 平台 ↔ 客户端 / 对外接入）

> 目标：把 zero-web-server 对 zmedia-server、对 zplayer/第三方 的接口**分类分组**统一，
> 并明确“访问 token 是什么”。原则：**只做 token 存在性/启用校验，不做接口级权限、不做限流**。
>
> 权威实现位置：`internal/mediakit/client.go`（平台→ZMS）、`internal/interfaces/http/middleware/auth.go`（用户 token）、
> `internal/application/accesstoken/`（对外接入 token）、`internal/interfaces/http/router/`（`/api/v1` 分组）。

---

## 1. 四个接口族

| 族 | 方向 | 前缀 | 鉴权 | 分组维度 |
|---|---|---|---|---|
| **A 控制面 API** | 平台 → ZMS | `/index/api/<域>/<动作>` | `?secret=`（节点密钥） | system / media / proxy / rtp / record / webrtc / onvif / gb28181 / device |
| **B 事件回调** | ZMS → 平台 | `/index/hook/<事件>` | 无（仅可信内网） | on_publish / on_play / on_stream_changed / on_stream_none_reader / on_record_mp4 / on_server_started / on_server_keepalive … |
| **C 业务 API** | 客户端/第三方 → 平台 | `/api/v1/<资源>/…` | `access-token` 头（用户 JWT） | user / group / play / playback / front-end(ptz) / device / alarm / accessToken / … |
| **D 流接入** | 外部推/拉流 | 流 URL `?token=` | 接入 token | 无（token 即凭证） |

约定：**新接口一律 `<族>/<域>/<动作>`**；A 族保留历史扁平名做别名（见 §4）。

---

## 2. 访问 token 三件套

| token | 用途 | 传输 | 存储 / 配置 | 校验点 |
|---|---|---|---|---|
| **用户 token** | 登录态（Web / zplayer） | 头 `access-token`（JWT） | 无状态签发 | `middleware.Auth` |
| **节点 secret** | 平台 ↔ ZMS 服务间 | 查询串 `?secret=` | 媒体节点页 → `zws_media_server.secret` ⟷ ZMS `conf/config.ini [api] secret` | ZMS `check_secret` |
| **接入 token** | 对外推/拉流、第三方调用 | 查询串 `?token=` | 新页面「接入鉴权」→ `zws_access_token` | 平台 token 服务 + ZMS 本地白名单 |

三者互不复用、互不回退：用户 token 不等于接入 token，接入 token 不携带用户身份。

---

## 3. 接入 token（对外提供）

- **页面**：运维管理 →「接入鉴权」（`/accessToken`），支持 新增 / 启用 / 停用 / 重置 / 编辑备注 / 删除 / 一键拷贝。
- **表**：`zws_access_token(id, name, token, enabled, remark, create_time, update_time)`。
- **后端**：`internal/application/accesstoken/`（服务）+ `persistence/access_token_repository.go` + `handler/access_token_handler.go` + `router/routes_access_token.go`；接口 `/api/v1/accessToken/*`，归属 `ops` 菜单权限。
- **判定**：命中“存在且启用”即放行，否则拒绝；不做接口权限、不限流。
- **同步**：token 集合变化时，平台把**启用中的 token** 推到所有在线媒体节点（`/index/api/auth/tokens`）；节点自注册/心跳时也重新推送，保证 ZMS 重启后自动恢复。

### 3.1 校验落点与语义

- ZMS 在推/拉流会话建立时调用 `zms_auth_check`。平台推送白名单后，ZMS 用**内置本地比对**（无网络 I/O、poller 线程安全）。
- **本轮只对外部“推流”强制 token**；播放保持放行，避免影响平台自身观看链路（WebRTC/FLV 走平台鉴权即可）。
- 默认安全：白名单为空 → ZMS 不启用验签、全放行，行为与升级前一致；只有页面里存在启用中的 token 时才生效。
- 平台 `on_publish` hook 同样从 `params` 读取 `token` 并校验（作为二道闸口；ZMS 侧为主）。

## 4. A 族路径映射（统一分组前缀，旧名保留为别名）

平台统一调用新路径；ZMS 侧通过 `normalize_api_path` 把新路径归一到旧名，**新旧同时可用**。

| 旧（扁平） | 新（分组） |
|---|---|
| version / health / getServerConfig / getApiList / getBufPoolStats / getStatistic | system/version · system/health · system/config · system/api_list · system/bufpool · system/statistic |
| getMediaList / getMediaInfo / isMediaOnline / close_stream / close_streams | media/list · media/info · media/online · media/close · media/close_all |
| addStreamProxy / delStreamProxy / listStreamProxy | proxy/add · proxy/del · proxy/list |
| openRtpServer / connectRtpServer / closeRtpServer / listRtpServer | rtp/open · rtp/connect · rtp/close · rtp/list |
| loadMP4File / downloadFile / deleteRecordFile / seekRecordStamp / setRecordSpeed | record/load · record/download · record/delete · record/seek · record/speed |
| getWebrtcStats / getWebrtcCapabilities / startWebrtcClient / getWebrtcClients / stopWebrtcClient | webrtc/stats · webrtc/capabilities · webrtc/client_start · webrtc/client_list · webrtc/client_stop |
| （已分组）onvif/* · gb28181/* · device/* | 保持不动 |
| webrtc / whep / whip（信令，非 API 表） | 保持原路径（浏览器经平台反代直连） |

新增（非映射）：`/index/api/auth/tokens` —— 平台→ZMS 同步接入 token 白名单。`health` 不要求 secret（探活）。
