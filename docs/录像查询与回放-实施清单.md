# 录像查询 + 录像回放 实施清单（Web 端）

> 目标：在 zero-web-server 管理端补齐「录像查询 → 选录像段 → 回放（时间轴/倍速/暂停/seek）」。
> 背景：后端能力已具备，缺口集中在前端；本文档为相机到货前的准备与对接契约，凭此可直接开工。
> 上游定位：Web 只做单路预览/单路回放 + 低并发云台控制，不做大屏多路（多路由 zplayer）。

---

## 1. 现状（已核对代码）

### 后端已具备
- 录像查询
  - GB28181：`playback.Service.QueryRecord` 发 SIP `RecordInfoQuery`、超时等待，返回 `record.RecordInfo`（[internal/domain/record/entity.go]）。
  - 插件：`ipcdevice.QueryRecord`（hik 插件具备 `record_query`）。
  - 统一口径：`asset.Service.QueryRecords → channeldrv.Driver.QueryRecords`（gb 转 playback.QueryRecord，plugin 转 ipc.QueryRecord；**onvif 不支持**，驱动无 playback 能力）。
- 回放
  - 统一口径：`asset.Service.StartPlayback/StopPlayback`（发回放 INVITE，ZMS `gb_playback.c` 拉设备录像流并转发）。
  - 旧口径：`/api/v1/playback/*` 全套 `Start/Stop/Pause/Resume/Speed/Seek`（按 streamId 控制）。
- 播放地址：`dto.StreamContent`（含 flv/ws_flv/hls/rtc/rtsp 等多出口 + duration/progress）。

### 前端缺口（明确的空）
- `web/src/api/playback.js` **只有** play/resume/pause/setSpeed/stop，**没有录像查询**；无任何页面调用 `playback/records`。
- 直播播放器 `views/channel/player.vue` / `views/device/dialog/devicePlayer.vue` **没有回放模式**（无时间轴、录像段选择、倍速、seek）。
- `views/channel/unified-panel.vue` 仅把「回放」作为能力图标展示，无入口。

## 2. 接口契约（前端对接用）

统一资源口径（推荐，前端只用 resourceId，来自 `/api/v1/channels` 行的 `resourceId`）：

| 用途 | 方法/路径 | 入参 | 返回 |
|---|---|---|---|
| 查录像段 | `POST /api/v1/resources/:id/playback/records` | body `{startTime,endTime,streamType}` | 设备/插件原始结构（GB 为 `RecordInfo`） |
| 起回放流 | `POST /api/v1/resources/:id/playback/start` | body `{startTime,endTime,stream:"main"/"sub"}` | `StreamContent` |
| 停回放流 | `POST /api/v1/resources/:id/playback/stop` | — | — |

回放过程的控制（暂停/倍速/定位），复用旧口径（只需回放流的 `stream`）：

| 用途 | 方法/路径 | 入参 |
|---|---|---|
| 暂停 | `GET /api/v1/playback/pause/:streamId` | streamId = StreamContent.stream |
| 恢复 | `GET /api/v1/playback/resume/:streamId` | 同上 |
| 倍速 | `GET /api/v1/playback/speed/:streamId/:speed` | speed：0.5/1/2/4… |
| 定位 | `GET /api/v1/playback/seek/:streamId/:seekTime` | seekTime 见下方约定 |

### 数据结构
- 录像段（GB）`RecordInfo`：`{ deviceId, channelId, name, sumNum, count, recordList:[{ name, startTime, endTime, type, fileSize, filePath, secrecy }] }`
  - `startTime/endTime` 为 **GB 时间字符串**（如 `2026-11-25T10:00:00`，注意可能是 `T` 分隔）。前端据二者计算段时长。
  - 插件返回为插件原始结构，前端按插件 capability 解析（先只支持 GB 即可，插件随后）。
- 播放地址 `StreamContent`：`{ app, stream, flv, ws_flv, hls, rtc, rtsp, videoCodec, duration, progress, ... }`
  - GB 回放 `duration/progress` 多半为 0（无服务端进度），**时间轴时长以录像段 endTime-startTime 为准**。

### seekTime 约定（需联调确认）
- 旧 `playback.js` 的 seek 入参语义以 handler 为准；GB 回放多为「以起始时刻为基准的绝对/相对秒」。相机到货后按实际行为定：优先“绝对时间(ms)”或“相对流起点秒数”，确定后固定到前端。

## 3. 任务拆解（按依赖顺序）

### T1 前端 API 层（0.5d）
改 `web/src/api/playback.js`，新增统一口径封装：
- `queryRecords(resourceId, { startTime, endTime, streamType })` → POST `/resources/:id/playback/records`
- `startPlayback(resourceId, { startTime, endTime, stream })` → POST `/resources/:id/playback/start`
- `stopPlayback(resourceId)` → POST `/resources/:id/playback/stop`
- 复用现有 `pause/resume/setSpeed/stop`（按 `StreamContent.stream`）。

### T2 录像查询面板（1~1.5d）
新增组件 `web/src/views/channel/common/recordQueryPanel.vue`（或 drawer）：
- 时间段选择（默认当天；快捷：今天/昨天/近7天）。
- 查询按钮 → `queryRecords` → 解析 GB `recordList`（插件结构后续）。
- 结果表：开始时间 / 结束时间 / 时长 / 类型 / 大小；点击某段 → 携带该段 `startTime/endTime` 触发回放。
- 空态「无录像」。

### T3 回放播放器（1.5~2d）
在现有播放器上加“回放模式”（`player.vue` 为主，`devicePlayer.vue` 同步）：
- 进入回放：`startPlayback(resourceId,{startTime,endTime,stream})` → 拿 `StreamContent` → 复用 `onStreamReady(content)` 起播。
- 时间轴：以录像段 `[startTime,endTime]` 为总长；进度跟随（无服务端进度时按本地时钟/或按 seek 后重算）。
- 控件：播放/暂停（pause/resume）、倍速（setSpeed）、拖动定位（seek）、停止。
- 关闭/切换段/切回直播时：`stopPlayback(resourceId)` 停流（避免后台一直拉）。
- 直播与回放状态互斥，UI 明确标识当前是「回放 某时间段」。

### T4 入口接入（0.5d）
- `unified-panel.vue`：把能力集里的「回放」做成可点入口（有 playback 能力且在线时）→ 打开 T2 面板。
- 播放器工具栏增加「录像/回放」按钮 → 打开 T2 面板（以当前通道 resourceId）。
- 设备编辑抽屉/资产卡片暂不加（保持资产页纯展示）。

### T5 PTZ 入口收敛（与回放并行，可选但建议）
- 播放器当前打老接口 `/api/v1/common/channel/front-end/*`；统一到 `channeldrv` 的 `/api/v1/front-end/*`（ptzapp），确保 ONVIF/插件相机也能云台。
- 验证 `derivePtzCaps` 与真实设备能力一致。

### T6 真机联调（1d，相机到货后）
见第 5 节清单。

## 5. 相机到货验证清单
1. 设备能注册到平台 SIP；`/api/v1/channels` 能列出其 `resourceId`。
2. **录像查询**：`POST /resources/:id/playback/records` 返回非空 `recordList`（确认相机开了 SD/录像且支持 GB 录像检索）。若为空，先查设备端录像配置/时间。
3. **回放起流**：`POST /resources/:id/playback/start` 返回带 `stream` 的 `StreamContent`，用现有播放器能出画面。
4. **暂停/倍速/定位**：`pause/resume/speed/seek` 实际生效；确认 `seekTime` 语义（绝对/相对），固定到前端。
5. **停流**：关闭回放后 ZMS 该路消失，设备不再被拉流。
6. **PTZ**：方向/变倍/预置位/巡航真机响应正常（第 T5 项）。

## 6. 工作量估计
- T1+T2+T4：约 2~2.5 天（录像查询面板 + 入口）。
- T3：约 1.5~2 天（回放播放器 + 时间轴/控制）。
- T5：约 1 天（PTZ 入口统一，可与上并行）。
- T6：约 1 天联调。
- 合计约 **5~6 人日**，前端为主，后端基本不动。

## 7. 风险/注意
- GB 录像查询依赖设备支持与已有录像；ONVIF 不支持录像查询（不提供入口）。
- GB 回放无服务端进度，时间轴以录像段时长为准，拖动定位靠 seek 实测语义。
- 播放地址可能多出口（flv/ws_flv/hls/rtc），复用现有播放器选路（playerStrategy）。
- 停流务必接：回放关闭/切段/切直播都要 stopPlayback，防止后台拉流。
